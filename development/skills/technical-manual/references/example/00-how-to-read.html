This book documents the safetensors file format as implemented by github.com/huggingface/safetensors at commit e246a25 (22 September 2026, git describe = v0.6.0-87-ge246a25, crate version string 0.9.0-dev.0). It covers the three regions of the file, the JSON header, the 22 dtype codes, the writer, the checks in the Rust reader, and the Python binding's loading paths.

It is written for an engineer who has called save_file and load_file from Python and wants to know exactly what is in the file and what a reader refuses. After reading it you can write a parser from the tables in the Reference part, predict the error the reference reader returns for a damaged file, and say how many bytes of memory a given load call occupies.

How it was made

Sources were ranked: Rust and Python source at the pinned commit first, then the prose specification in README.md, then docs/safetensors.schema.json, then files on disk, then the project's other documentation. Where two disagree the higher one wins and the text says so. The disagreements are collected in Where README, schema and code disagree.

The reference library used for every experiment is the Python package built from the pinned commit itself (pip install of bindings/python, which reports 0.9.0-dev.0), not the 0.8.0 release on PyPI. The commit is 87 commits past the last tag reachable by git describe and contains the pread backend and get_tensor_meta, which the book uses.

The machine this book was built on can reach GitHub and PyPI and cannot reach huggingface.co. No published model file was downloaded. Every specimen below was written locally by research/make_specimens.py with the reference library and numpy 2.5.3. Statements about "every specimen" are statements about these five files and about no file on the Hub.

Conventions

Offsets. Decimal in prose and tables, counted from byte 0 of the file unless called relative, in which case they count from the first byte of the data section. Hex dumps label rows in hexadecimal. A range written [a, b) includes a and excludes b.

Units. B is bytes. MiB is 220 bytes. MB, where the source uses it, is quoted as the source wrote it; the header limit in code is the decimal number 100,000,000.

Names. N is the value of the first eight bytes. Type codes are written as they appear in the file: F32, BOOL. Source locations look like tensor.rs:402 and always refer to commit e246a25; tensor.rs means safetensors/src/tensor.rs and lib.rs means bindings/python/src/lib.rs.

Kinds of fact. "The README says" and "the schema says" quote a document. "The reader checks" cites code. "Measured" means a script in research/ printed the number on the build machine (Linux 6.18, x86-64, 2 CPUs, CPython 3.13.16). Figures carry the same word in their tag. Paths that were read but not run are labelled from source, not run.

Cross-references. A reference to another section prints its page; a reference to a figure prints its number.

k0padding, elided or unused

How the parts are ordered

1 Orientation. The three regions, the reason the format exists, and which description of it is authoritative.

2 The file, byte by byte. The length prefix and the data section, with two files decoded by hand.

3 The JSON header. Tensor entries, __metadata__, the JSON dialect, header size.

4 Tensors and dtypes. The 22 codes, byte and element order, shapes.

5 How files are written. Sort order, padding, the atomic rename, and what the numpy front end does not check.

6 What readers check. read_metadata and validate line by line, 54 hand-built files, and what is left unchecked.

7 Loading in practice. safe_open, copies, the two backends, slicing, the torch paths, and reading a header remotely.
