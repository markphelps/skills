Files from the Hub. No published model was examined. Nothing here says what real checkpoints contain, how large their headers are, or which __metadata__ keys they carry.

torch, tensorflow, flax, mlx, paddle. None is installed. Their loading and saving paths are described from source and marked so. Whether torch's CPU path is in fact copy-free, and how it behaves on misaligned tensors, was not observed.

GPU and MPS paths, prefetch. Read only. The project's speed statements about them are quoted as the project's.

Cold-cache and network-filesystem performance. All timings had the file in the page cache on one 2-CPU virtual machine.

Big-endian hosts, 32-bit targets, Windows, macOS, no_std. Behaviour there is inferred from the source where stated and otherwise not discussed.

Other implementations. The JavaScript parser mentioned in the project's documentation and any third-party reader were not examined. "The reader" means the Rust reference only.

Released versions. The book describes commit e246a25. Which behaviours hold in the 0.8.0 wheel or will hold in 0.9.0 was not checked.

Sub-byte element packing. The bit order of two F4 elements within a byte, and the encodings of the 4-, 6- and 8-bit float codes, are not defined in the Rust source and are not described here.

File mode under other umasks. The 0600 mode after save_file was observed once, as root, on one filesystem.

Why open time grows faster than linearly past 10,000 tensors. Measured, not explained.
